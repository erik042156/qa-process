# Feature PRD - 상품 검색

## 1. 개요

automationexercise.com의 Products 페이지(`/products`)에 있는 "Search Product" 검색창에
실제로 검색어를 입력해 검색을 실행했을 때의 동작(검색 결과 노출 방식, 검색 결과 없음
케이스, 빈 검색어 케이스)을 다룬다.

검색창이라는 화면 구성요소가 Products 페이지에 "존재한다"는 사실 자체는
`page-ui.md`(REQ-PAGE-UI-009)에서 이미 다뤘으므로 본 문서에서는 재기술하지 않는다.

CATEGORY/BRANDS 클릭을 통한 상품 필터링(카테고리·브랜드 기준 상품 목록 노출)은 이번
Feature PRD 작성 과정에서 사용자가 "상품 검색" Feature의 범위를 "Products 페이지
검색창(키워드 검색)"으로만 한정하기로 확정함에 따라 본 문서의 범위가 아니다. 해당 내용은
`page-ui.md`로 이관되어 REQ-PAGE-UI-022~024로 반영되었다(2. 관련 Project PRD 참조, 7. 비고
참조).

    검색창과 돋보기 아이콘 버튼이 나란히 배치되어 노출된다는 사실(화면 구성요소로서의

- `/docs/prd/feature/cart.md` (승인완료)
  - 상품 상세 페이지의 존재 및 "장바구니 담기 시 수량 지정 가능" 사실만 장바구니 관점에서
    기록되어 있으며, 상세 페이지 자체의 UI/기능은 본 문서에서도 다루지 않는다(5. Out of
    Scope, 7. 비고 참조).

## 3. 사용자 조작 시나리오

1. Products 페이지(`/products`)에 진입해 "Search Product" 검색창에 실제 상품과 매칭되는
   검색어(예: "shirt")를 입력하고 돋보기 아이콘 버튼을 클릭해 검색을 실행한다.
2. 검색 결과 화면(URL, 섹션 제목, 노출되는 상품 카드)을 확인한다.
3. 결과가 없을 것으로 예상되는 무의미한 검색어를 입력해 검색을 실행하고, 결과 없음
   상태의 화면을 확인한다.
4. 검색어를 비운 채(빈 문자열) 검색을 실행해 화면과 URL의 변화를 확인한다.

## 4. Requirements

### 4.1 확인된 요구사항

**검색어 입력 및 검색 실행**

- **REQ-PRODUCT-SEARCH-001**: Products 페이지 검색창에 검색어를 입력하고 검색을 실행하면,
  입력한 검색어와 매칭되는 상품만 노출된다(매칭 기준은 REQ-PRODUCT-SEARCH-005 참조). 이때
  URL은 `https://automationexercise.com/products?search={검색어}` 형태로 변경되며(예:
  `?search=shirt`), 상품 목록 상단 섹션 제목이 기존 "ALL PRODUCTS"에서 "SEARCHED PRODUCTS"로
  바뀌어 노출된다.
- **REQ-PRODUCT-SEARCH-002**: 검색 결과 상품 카드의 구성(이미지/가격/상품명/Add to
  cart/View Product)은 `page-ui.md`의 ALL PRODUCTS 그리드(REQ-PAGE-UI-011)와 동일하다.

**검색 결과 없음 케이스**

- **REQ-PRODUCT-SEARCH-003**: 매칭되는 상품이 없는 검색어로 검색을 실행하면 "SEARCHED
  PRODUCTS" 제목은 동일하게 노출되지만 그 아래에는 상품 카드 없이 빈 목록 영역만
  노출된다. 별도의 "결과 없음(No Result)" 안내 문구는 노출되지 않는다(스크린샷 기준 확인).

**빈 검색어 케이스**

- **REQ-PRODUCT-SEARCH-004**: 검색어를 입력하지 않은 채(빈 문자열) 검색을 실행하면 전체
  상품이 노출된다(Products 페이지 원본의 ALL PRODUCTS와 동일하게 전체 상품이 보임). 다만
  이때도 URL은 `?search=` 형태로 남아, 검색을 실행하지 않은 Products 페이지 원본 URL과는
  구분된다.

**검색 매칭 알고리즘 및 노출 방식**

- **REQ-PRODUCT-SEARCH-005**: 검색 매칭은 상품명(Product Name), 하위 카테고리명(예: Tops,
  Dress, Tshirts, Jeans, Saree 등) 등 상품과 직접 연관된 텍스트 중 어느 하나라도 검색어와
  부분 일치(substring match)하면 노출된다. 브랜드명은 부분 일치·완전 일치 여부와 무관하게
  매칭 대상에서 항상 제외된다. 상위 카테고리명(Women/Men/Kids)이 매칭 대상에 포함되는지
  여부는 이번 확인으로 증명되지 않았다(관찰된 매칭은 상품명 문자열에 해당 단어가 리터럴로
  포함되어 발생한 것으로 확인됨) — 4.2 미확인 항목 참조.
- **REQ-PRODUCT-SEARCH-006**: 검색 결과 상품 수가 많을 경우 별도의 페이지네이션 없이
  스크롤을 통해 이어서 확인하는 방식으로 노출된다(`page-ui.md` REQ-PAGE-UI-021과 동일한
  패턴).

**검색 실행 방법**

- **REQ-PRODUCT-SEARCH-007**: 검색은 반드시 돋보기 아이콘 버튼을 클릭해야만 실행된다.
  검색창에 검색어를 입력한 상태에서 Enter 키를 입력해도 검색이 실행되지 않는다.

**입력값 검증**

- **REQ-PRODUCT-SEARCH-008**: 검색어 입력값에 대한 별도의 클라이언트 측 검증(길이 제한,
  특수문자 제한 등)이 없어 모든 문자를 제한 없이 입력할 수 있다. 매칭 로직은
  REQ-PRODUCT-SEARCH-005와 같이 입력된 텍스트가 상품 관련 텍스트(상품명, 카테고리명 등)에
  포함되는지 여부만으로 판단하는 단순 구조이며, 브랜드명은 부분 일치·완전 일치 여부와
  무관하게 이 판단에서 항상 제외된다.

### 4.2 미확인 / 추가 확인 필요 항목

- 상위 카테고리명(Women/Men/Kids) 자체가 검색 매칭 필드에 포함되는지 여부(현재까지 관찰된
  매칭은 모두 상품명 substring 매칭으로 설명 가능하며, 상위 카테고리명이 별도 매칭 필드라는
  직접 증거는 없음)

## 5. Feature 단위 In Scope / Out of Scope

**In Scope**

- Products 페이지 검색창에서의 키워드 검색 실행 동작(매칭 상품 노출, URL 변경, 섹션 제목
  변경)
- 검색 결과 없음 케이스의 화면 동작
- 빈 검색어로 검색 실행 시의 동작

**Out of Scope**

- 검색창 자체가 화면 구성요소로서 존재한다는 사실 — `page-ui.md` REQ-PAGE-UI-009 범위
- CATEGORY/BRANDS 클릭을 통한 상품 필터링 동작 — 사용자 확정에 따라 `page-ui.md` 범위로
  재조정됨(REQ-PAGE-UI-022~024, 7. 비고 참조)
- 상품 상세 페이지 자체의 UI/기능 — Project PRD 대상 Feature 목록에 아직 없으며, 향후
  Project PRD 갱신 후 별도 Feature PRD로 다룰 예정(현재는 미확정 계획). 본 문서에서는
  검색 결과 상품 카드의 "View Product" 링크를 통해 상품 상세 페이지로 이동할 수 있다는
  구조 자체(REQ-PRODUCT-SEARCH-002, page-ui.md REQ-PAGE-UI-011 참조)만 다루며, 상세
  페이지 진입 후의 UI/기능은 포함하지 않는다.
- 장바구니 담기, 결제 등 검색 결과 이후의 다른 기능 동작 — `cart.md` 등 해당 Feature PRD
  범위

## 6. 예외 / 에러 케이스

- 매칭되는 상품이 없는 검색어를 입력했을 때 상품 카드 없이 빈 목록 영역만 노출되고 별도
  안내 문구는 없는 케이스 (REQ-PRODUCT-SEARCH-003)
- 검색어를 입력하지 않고 검색을 실행했을 때 전체 상품이 노출되지만 URL은 검색 미실행
  상태와 다르게 유지되는 케이스 (REQ-PRODUCT-SEARCH-004)
- 4.2에 정리된 미확인 항목(매칭 알고리즘 상세, 입력값 검증 등)은 아직 예외 케이스로
  확정되지 않았으므로 이 절에 포함하지 않았다.

## 7. 비고

- **CATEGORY/BRANDS 필터링과의 경계**: 최초 `page-ui.md` 작성 시점에는 CATEGORY/BRANDS
  클릭 필터링 로직과 검색창 검색 동작이 모두 "상품 검색" Feature로 위임되어 있었으나, 본
  문서 작성 과정에서 사용자가 "상품 검색" Feature를 "Products 페이지 검색창(키워드 검색)"
  으로만 한정하기로 확정했다. 이에 따라 CATEGORY/BRANDS 필터링 관련 내용은 본 문서가
  아니라 `page-ui.md`에 REQ-PAGE-UI-022~024로 반영했다. `page-ui.md`는 이미 승인완료
  상태였던 문서이므로 해당 변경은 재승인 대상이며, 재승인은 사용자 본인의 직접 확인을
  거쳐 별도로 처리된다.
- **상품 상세 페이지 관련 경계**: 검색 결과 화면에서 "View Product" 클릭 시 상품 상세
  페이지로 이동한다는 구조는 존재한다. 본 문서 작성 이후 Project PRD가 갱신되어 "5. 대상
  Feature 목록"과 "6. In Scope"에 "상품 상세"가 추가되었으나(사용자 재승인 완료,
  2026-08-21), 상세 페이지 자체를 다루는 Feature PRD는 아직 별도로 작성되지 않았다. 본
  문서에서는 이동 구조 자체만 언급하고 상세 페이지 UI/기능은 포함하지 않았다.
- 최초 작성 시 4.2 미확인 항목이었던 검색 매칭 알고리즘 상세 규칙, 검색 결과 다수일 때
  노출 방식, Enter 키를 통한 검색 실행 가능 여부, 입력값 검증 존재 여부는 이후 사용자가
  직접 확인해 확정되었다. 이에 따라 REQ-PRODUCT-SEARCH-005~008로 4.1에 반영하고 4.2는
  "현재 없음"으로 정리했다.
- **검색 매칭 알고리즘 정정(2026-08-31)**: 최초 승인 시(2026-08-21) REQ-PRODUCT-SEARCH-005는
  "상품명 기준 부분 일치로만 동작하며 카테고리명·브랜드명은 매칭 대상이 아니다"로 확정되었으나,
  이후 자동화 테스트 실행 과정에서 `?search=shirt` 결과 중 상품명에 "shirt"를 포함하지 않는
  Top류 상품 4건("Sleeves Printed Top - White" 등)이 노출되는 것이 Selenium/Playwright
  양쪽에서 독립 재현되어 기존 REQ와 실제 사이트 동작이 불일치함이 발견되었다. 사용자가 실제
  사이트 동작을 재확인해 "상품명 또는 하위 카테고리명(예: Tops/Dress/Tshirts 등) 중 하나라도
  일치하면 노출되며, 상위 카테고리명(Women/Men/Kids)과 브랜드명은 매칭 대상이 아니다"로
  사양을 확정함에 따라 REQ-PRODUCT-SEARCH-001/005/008을 정정했다. 이 REQ들을 근거로 이미
  승인완료 상태였던 `docs/tc/product-search.md`의 TC-PRODUCT-SEARCH-001/005/006(모두 자동화
  대상으로 확정되어 자동화 코드까지 구현된 상태)은 본 정정에 따라 tc-agent에서 별도로
  재검토가 필요하다.
- **검색 매칭 대상 재정정(2026-08-31, 2차)**: TC-PRODUCT-SEARCH-006 자동화 실행 중 상위
  카테고리명(women/men/kids) 검색어에서도 결과가 노출되는 현상이 발견되었으나, 원인 분석
  결과 이는 상품명(예: "Madame Top For Women", "Men Tshirt")에 해당 단어가 리터럴로
  포함되어 있었기 때문으로 확인되었다. 사용자가 이를 근거로 매칭 규칙을 재확인해, "상품명
  또는 하위 카테고리명" 두 필드로 한정했던 기존 표현을 "상품명, 하위 카테고리명 등 상품과
  직접 연관된 텍스트"로 일반화하고, 브랜드명은 완전 일치를 포함해 예외 없이 항상 매칭
  대상에서 제외됨을 명시하도록 REQ-PRODUCT-SEARCH-005/008을 정정했다. 상위 카테고리명
  (Women/Men/Kids)이 매칭 필드에 포함되는지는 여전히 미확인 상태로 남겨 4.2에 반영했다.
  관련 TC-PRODUCT-SEARCH-001/005/006/008은 tc-agent가 본 정정에 따라 재검토한다.
